# DetCore Virtual Time: Architecture, History, and Related Work

This document explains how DetCore turns deterministic execution progress into
guest-visible time. It is written against Hermit commit
[`2f3689bd`](https://github.com/rrnewton/hermit/tree/2f3689bd8830ab6b59dacea6cb72951f4d0d899e).
All Hermit source links are immutable links to that revision.

The short version is:

- Each guest thread has a local progress clock, `DetTime`, derived from
  intercepted system calls, retired conditional branches (RCBs), special
  instructions, and explicit deterministic advances.
- `GlobalTime` adds the local progress of all threads to one epoch and to time
  generated by the scheduler. It is a serialized-work clock, not host wall
  time and not the elapsed time of several CPUs running in parallel.
- The scheduler commits one thread at a time. It uses logical time for
  timeslices and deadlines, but the ordinary run queue is priority followed by
  deterministic round robin, not minimum virtual time.
- Guest time syscalls normally read the aggregate clock. `RDTSC` currently
  reads the calling thread's local clock. A shared monotonic `GuestClock` floor
  prevents time from moving backward across a process tree.
- Chaos mode changes deterministic priorities, timeslices, and optionally the
  rate at which a thread's RCBs consume virtual time. A fixed seed and
  configuration reproduce those choices.

## 1. Terms and Mental Model

**Logical time** is an integer count expressed in virtual nanoseconds. The
nanosecond unit gives Linux APIs a familiar scale; it is not a measurement of
host elapsed nanoseconds.

**Local time (`DetTime`)** measures progress attributable to one guest thread.
It retains separate counters so logs and serialized artifacts can explain the
source of the time.

**Global time (`GlobalTime`)** is the epoch plus the sum of local work reported
by every thread plus scheduler-generated time. It is the clock used to judge
absolute deadlines.

**Committed time** is the scheduler's snapshot of global time at a scheduling
commit. It is not a third independent clock.

**Guest clock (`GuestClock`)** is a monotonic floor over the raw observation a
backend supplies to a guest-visible clock read. It preserves one absolute
clock domain across fork and exec.

**RCB** means retired conditional branch. On supported x86-64 hardware, a PMU
counter provides a repeatable progress signal and a repeatable place to
preempt CPU-only code. RCB counts are more productive than syscall counts: a
thread cannot do arbitrary CPU work forever without retiring a branch.

### What machine is DetCore modeling?

DetCore is not an implementation of Linux CFS, EEVDF, or another particular
Linux scheduler. Linux owns the host tasks, while DetCore controls which
stopped task may continue at an intercepted event or RCB-preemption boundary.
The default abstract machine has **one serialized logical execution resource**
and a deterministic commit order. The implementation describes this as
cooperative sequentialization reinforced by RCB preemption
([architecture lines 404-468](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/docs/ARCHITECTURE.md#L404-L468)).

It is also not an `N`-CPU simulator with smooth parallel elapsed time. The
aggregate clock adds every thread's work; it does not take the maximum clock
of `N` CPUs. Chaos explores seeded schedules of this serialized machine. The
`--no-sequentialize-threads` option delegates concurrency to Linux and weakens
schedule reproducibility rather than defining a deterministic multiprocessor
([user guide lines 383-402](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/docs/USER_GUIDE.md#L383-L402)).

## 2. Current Architecture

### 2.1 Scalar representation

`LogicalTime` wraps a `u64` count of virtual nanoseconds. It provides exact
unit conversion and saturating addition for far-future deadlines
([definition and conversions](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L105-L198),
[saturating addition](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L264-L290)).
The default epoch is `2026-01-01T00:00:00Z`, configurable through
`--epoch`/`HERMIT_EPOCH`
([configuration](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/config.rs#L140-L176),
[default](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/config.rs#L1046-L1050)).

The epoch makes timestamps plausible to software that rejects 1970-era file
times. It does not import host wall time into the execution.

### 2.2 Per-thread progress

For thread `i`, the current implementation can be summarized as:

```text
L_i = E + X_i + M * (S_i + 10 * R_i + 25 * N_i)
```

where:

- `E` is the configured epoch in nanoseconds;
- `X_i` is an explicit deterministic advance, such as advancing a resumed
  thread to its own scheduled deadline;
- `M` is `--clock-multiplier`, plus the legacy no-RCB inflation when active;
- `S_i` is the sum of deterministic, category-specific syscall costs;
- `R_i` is the thread's RCB progress, possibly weighted by a deterministic Q32
  per-thread multiplier in chaos slowdown mode; and
- `N_i` counts nondeterministic instructions such as `RDTSC` and `CPUID`.

The constants are 10 ns per RCB, 25 ns per nondeterministic instruction, and
500,000 ns per scheduler step
([constants](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L35-L98)).
`DetTime`'s fields, compatibility defaults, and exact projection are in
[`time.rs` lines 374-437](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L374-L437)
and
[`lines 506-665`](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L506-L665).

The syscall cost table models representative overhead, never observed host
latency. It ranges from 250 ns for fast identity calls to 250,000 ns for
process operations, with a positive fallback for unknown calls
([cost table](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/syscall_time.rs#L9-L158)).
Every intercepted syscall is charged after entry
([charging site](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/lib.rs#L1444-L1457)).

RCB progress is read before handlers and converted to local time
([RCB update path](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/lib.rs#L353-L389)).
If RCB time is disabled, DetCore multiplies sparse event costs so the virtual
clock remains useful; PMU preemption and RCB accounting are separate controls
([configuration semantics](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/config.rs#L470-L475),
[`use_rcb_time`](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/config.rs#L631-L637)).

### 2.3 Aggregate progress

`GlobalTime` maintains:

```text
G = E + sum_i(L_i - E) + X_scheduler
```

`time_vector[i]` stores only thread `i`'s work since the epoch. `extra_time`
stores central advances not attributable to a guest thread. `total` caches the
sum and is checked against a recomputation
([structure and update](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L705-L779),
[sum and scheduler advance](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L781-L809)).

This sum has two important consequences:

1. It roughly models the elapsed work of one core, as the implementation says
   explicitly
   ([`as_nanos`](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L857-L863)).
2. A thread's local clock does not equal the aggregate. Other threads' work and
   scheduler time are intentionally absent from `threads_time(i)`.

At each global RPC, the caller sends its `DetTime`; global state updates that
thread's vector component before handling the request. A response can advance
the local clock to a deterministic value supplied by the scheduler
([send/update path](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/tool_global.rs#L2062-L2092)).
That response tracks the thread's own slice or a scheduled wakeup, not the sum
of all threads.

### 2.4 Scheduler coupling

The scheduler serializes requests through a seven-step transactional loop. It
tentatively selects a thread, checks whether the request can proceed, commits
or undoes the selection, and then requeues or blocks the thread. The ordinary
run queue key is `(priority, round_robin_turn)`
([queue contract and key](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/scheduler/runqueue.rs#L9-L116)).
With equal priorities, a committed turn moves the thread to the back of its
band, providing the documented `N - 1` same-priority turn bound
([user guide lines 404-420](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/docs/USER_GUIDE.md#L404-L420)).

Before each ordinary committed turn, `bump_global_time` reports the caller's
local time, adds the fixed scheduler increment, snapshots the aggregate, and
monotonically advances `Scheduler::committed_time`
([implementation](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/scheduler.rs#L2473-L2561)).
Timed sleeps, timeouts, alarms, and POSIX timers are ordered separately by
absolute `LogicalTime`
([timed-event structure](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/scheduler/timed_waiters.rs#L19-L76)).
When no runnable thread exists, the scheduler can advance directly to the next
timed event rather than waiting for host time.

The fixed scheduler charge guarantees that repeated committed scheduling
opportunities advance time even if thread-local event counters do not. It also
means global time is sensitive to scheduler-turn count. This is a deliberate
productivity mechanism and a recurring design pressure; it must not be
silently removed, rounded, or frozen to solve an unrelated scheduling issue.

### 2.5 Timeslices and PMU preemption

`--max-timeslice` is an RCB-enforced upper bound; `--target-timeslice` is a
cheaper logical target checked at intercepted boundaries
([options](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/config.rs#L390-L410)).
`ThreadState::next_timeslice` derives absolute local deadlines and handles
recorded preemption replay
([implementation](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/tool_local.rs#L1848-L1960)).

The PMU can interrupt CPU-only work between syscalls. At each intercepted
boundary DetCore accounts the exact RCB delta since the prior observation.
This makes the logical trajectory depend on deterministic guest progress, not
on how long the host happened to run the thread.

### 2.6 Guest-visible reads and deadlines

`time`, `gettimeofday`, and `clock_gettime` call `guest_clock_time`. By default
it obtains `GlobalTimeLowerBound`; a backend-specific internal option can use
the local thread clock. Both pass through the process-tree-wide monotonic
`GuestClock`
([selection](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/syscalls/time.rs#L94-L107),
[handlers](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/syscalls/time.rs#L171-L224),
[monotonic floor](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/tool_local.rs#L1162-L1179)).
The global lower bound is a read of the aggregate after the RPC has reported
the calling thread's current local time
([RPC handler](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/tool_global.rs#L908-L910),
[observation helper](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/tool_global.rs#L2438-L2459)).

Relative sleeps add a duration to that clock; absolute sleeps and timers use
the same absolute domain as `committed_time`
([sleep requests](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/syscalls/time.rs#L117-L137)).
Keeping reads and deadlines in one domain is essential: subtracting a
per-exec origin can create a new absolute deadline that is already in the
scheduler's past.

`RDTSC` is a current exception. DetCore charges one nondeterministic
instruction and returns the calling thread's `DetTime`, treating one virtual
cycle as one virtual nanosecond
([handler](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore/src/lib.rs#L1004-L1041)).
The source contains an explicit TODO to use global time there.

### 2.7 Chaos and replay

Chaos mode is deterministic schedule exploration. Separate seeded streams
drive application randomness, scheduler choices, and per-thread chaos choices
([architecture lines 755-790](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/docs/ARCHITECTURE.md#L755-L790)).

The optional slowdown mode maps `(scheduler seed, deterministic thread id,
logical-time epoch)` to a positive Q32 multiplier. The multiplier changes how
that thread's RCBs contribute to virtual time. Fixed-point accumulation makes
the result independent of backend batching
([representation](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L41-L92),
[weighted accumulation](https://github.com/rrnewton/hermit/blob/2f3689bd8830ab6b59dacea6cb72951f4d0d899e/detcore-model/src/time.rs#L569-L589)).
Epoch transitions and exact RCB targets are stored in preemption artifacts so
replay restores the same boundaries rather than redrawing from ambient state.

## 3. Invariants and Boundaries

The architecture relies on these invariants:

1. **No host wall time in guest logical time.** Cost inputs are deterministic
   counters, fixed tables, seeded functions, or recorded replay state.
2. **Monotonic local components.** `GlobalTime::update_global_time` rejects a
   thread component that moves backward.
3. **One epoch per aggregate.** The epoch is included once in `GlobalTime`, not
   once per thread.
4. **One absolute deadline domain.** Guest time reads, scheduler committed
   time, and virtual timer deadlines must be comparable without origin
   conversion.
5. **Fine-grained progress is product behavior.** Correctness is not achieved
   by freezing, rounding, resetting, or coarsening the clock.
6. **Serialized mode is the deterministic scheduling contract.** Letting
   Linux run guest threads concurrently weakens that contract.
7. **Blocked is not runnable.** A run-queue fairness policy cannot select a
   thread absent from the queue; wakeup and admission are separate mechanisms.

The model still has explicit boundaries. External input must be recorded,
isolated, or accepted as nondeterministic. PMU-backed preemption depends on
supported hardware. The aggregate sum is a useful deterministic clock, not a
claim of physical timing fidelity. Category costs are policy constants, not a
microbenchmark of the current host.

## 5. Related Work

This section incorporates the earlier
[`RELATED_WORK` survey](https://github.com/rrnewton/dev-hermit/blob/5d55af2a331ce97d604ef9053dc795d8145d3cb3/experiments/linux/RELATED_WORK.md)
from the "are we first to bitwise-deterministically boot Linux" inquiry. That
survey separates **a-priori determinism**, where fresh executions agree
without sharing a trace, from **deterministic replay**, where later executions
consume a recording of the first. DetCore primarily targets the first class;
its preemption and schedule artifacts also support replay and diagnosis.

### 5.1 dettrace: the direct predecessor

[Reproducible Containers (ASPLOS 2020)](https://doi.org/10.1145/3373376.3378519)
and its [Dettrace implementation](https://github.com/dettrace/dettrace/tree/657ff07bbfad5bac5ce680c412d66acb1008ae3b)
determinize ordinary Linux applications using ptrace and namespaces.

Dettrace's time model is coarser than DetCore's. Each process has a
microsecond-resolution logical clock and fixed step
([state definition](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/include/state.hpp#L55-L89),
[increment operation](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/include/state.hpp#L281-L289)).
It advances when time becomes observable and immediately preempts the caller;
`clock_gettime`, `gettimeofday`, and `time` show the pattern
([`clock_gettime`](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/src/dettraceSystemCall.cpp#L155-L173),
[`gettimeofday`](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/src/dettraceSystemCall.cpp#L1048-L1063),
[`time`](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/src/dettraceSystemCall.cpp#L2438-L2455)).
Its scheduler uses two PID-ordered heaps and rotates to the blocked heap when
the runnable heap is empty
([policy](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/include/scheduler.hpp#L13-L25),
[selection](https://github.com/dettrace/dettrace/blob/657ff07bbfad5bac5ce680c412d66acb1008ae3b/src/scheduler.cpp#L148-L165)).

DetCore keeps the a-priori container model but adds RCB-derived continuous
progress, a global aggregate, deadline fast-forward, PMU preemption, explicit
schedule replay, and a priority/round-robin queue. The local checkout used for
this source audit is `ignored/dettrace` at
`657ff07bbfad5bac5ce680c412d66acb1008ae3b`; it is intentionally ignored and
is evidence, not vendored project source.

### 5.2 Kendo and minimum logical clocks

[Kendo (ASPLOS 2009)](https://doi.org/10.1145/1508244.1508256)
orders synchronization by per-thread deterministic logical clocks derived
from retired stores. A thread may perform a synchronization operation when
its clock is the unique minimum. Waiting threads must advance their clocks;
otherwise a minimum-clock spinner can prevent the producer it needs from
running. Kendo also needs per-lock ordering to avoid unfair tie behavior.

DetCore borrowed the useful idea that deterministic instruction progress can
name repeatable execution positions. It did **not** adopt `argmin(local time)`
as its general run-queue rule. Local time is an output of guest progress and
feeds guest-visible deadlines; priority is the deliberate schedule-search
actuator.

This distinction is backed by a failed Hermit experiment, not only by theory.
The branch `study/min-vtime-scheduler-prototype` at local SHA `d2dc977e` tried
Kendo-style minimum per-thread virtual runtime. The durable report is
[`ai_docs/min-vtime-scheduler-study.md`](https://github.com/rrnewton/dev-hermit/blob/babd90aeeb517682bee90ad5b8585d68b02b70b8/ai_docs/min-vtime-scheduler-study.md).
On `make -j8`, excluding polling turns let one minimum-vtime waiter monopolize
254,860 turns. Charging polling turns produced two nearly equal waiters, but
99.4% of turns were still internal polling while productive compiler threads
received about 105 turns each. Both variants timed out after 300 seconds;
priority/FIFO completed in 4.25 seconds. Charging changed one monopolist into
two fair monopolists. It did not schedule the producers that would satisfy
their waits. This is why DetCore should not replace queue selection with a
global minimum-time rule while blocking is represented partly by polling.

### 5.3 Deterministic multithreading and operating systems

The broader a-priori family mostly uses deterministic quanta, fixed tokens, or
structured merge points rather than minimum virtual time:

| System | Mechanism | Relationship to DetCore time |
| --- | --- | --- |
| [DMP (ASPLOS 2009)](https://doi.org/10.1145/1508244.1508255) | Deterministic instruction-count quanta and a token for globally visible operations. | Shows how bounded quanta and deterministic commit can define an `N`-CPU model. DetCore currently defines one serialized resource instead. |
| [CoreDet (ASPLOS 2010)](https://doi.org/10.1145/1736020.1736029) | Parallel execution phases followed by deterministic serial commit. | The closest reference if Hermit ever defines multiple logical CPUs. Adopting it would be an architectural model change, not a run-queue tweak. |
| [DThreads (SOSP 2011)](https://doi.org/10.1145/2043556.2043587) | Processes isolate nominal threads; synchronization phases reconcile state in deterministic order. | Demonstrates phase/token determinism without making guest wall time equal instruction progress. Its memory-isolation runtime is not directly applicable to syscall interception. |
| [dOS (OSDI 2010)](https://www.usenix.org/conference/osdi10/deterministic-process-groups-dos) | Kernel-supported deterministic process groups with controlled communication. | Similar a-priori goal at process-group scope, but it changes the OS abstraction rather than running unmodified Linux applications under an external tool. |
| [Determinator (OSDI 2010)](https://www.usenix.org/legacy/events/osdi10/tech/full_papers/Aviram.pdf) | A purpose-built OS exposes deterministic spaces and explicit fork/join state reconciliation. | Avoids unconstrained shared-memory interleaving by construction. It is not a Linux scheduler or a virtual-clock policy for unmodified programs. |

The transfer to DetCore is bounded-service accounting and deterministic commit
order, not any one system's physical-time model. A future `N`-CPU DetCore
would need explicit CPU assignment, parallel phases, conflict ordering, and a
definition of whether guest elapsed time is a maximum, a sum, or another
aggregate.

### 5.4 Replay systems

Replay systems solve a different problem but share useful mechanisms:

- [rr](https://rr-project.org/) serializes Linux userspace threads on one core
  and uses RCBs to return to recorded asynchronous events. Its RCB "ticks" are
  repeatable execution coordinates, as in DetCore, but rr records the first
  run's schedule rather than prescribing the same fresh schedule.
- [PANDA](https://panda.re/) records whole-system nondeterminism in QEMU and
  replays it with a VM snapshot and event log
  ([record/replay documentation](https://github.com/panda-re/panda/blob/dev/panda/docs/manual.md#recordreplay-details)).
- [ReVirt (OSDI 2002)](https://www.usenix.org/conference/osdi-02/revirt-enabling-intrusion-analysis-through-virtual-machine-logging-and-replay)
  logs nondeterministic VM events for later instruction-level analysis.
- [SimuBoost (2019)](https://publikationen.bibliothek.kit.edu/1000097700)
  checkpoints a fast run and replays intervals in parallel simulation.
- [Arnold/Eidetic Systems (OSDI 2014)](https://www.usenix.org/conference/osdi14/technical-sessions/presentation/devecsery)
  records long-horizon machine-state lineage for retrospective reconstruction.

DetCore combines a-priori determinization with optional schedule/preemption
artifacts. Those artifacts make a selected chaos execution reproducible and
diagnosable, but the normal forward run does not require a trace from a prior
nondeterministic execution.

## 6. Design Lessons

1. Count progress that a CPU-only thread cannot avoid. RCBs closed the
   productivity gap in the original syscall-only clock.
2. Keep local work and aggregate elapsed execution distinct. They answer
   different questions and should not be silently substituted.
3. Keep guest reads and deadlines in one absolute clock domain across fork and
   exec.
4. Preserve fine-grained monotonic time. A test made green by freezing,
   rounding, resetting, or coarsening time has hidden the trajectory it was
   supposed to verify.
5. Do not confuse deterministic scheduling with simulation of Linux's
   scheduler. Priority/FIFO and chaos are policy tools for reproducible order.
6. Do not confuse a repeatable progress counter with a fair queue. Kendo-style
   minimum-vtime selection failed against DetCore's polling-based blocking even
   when pollers were charged.
7. If the machine model changes from one serialized resource to `N` logical
   CPUs, specify the clock aggregation and commit protocol first. DMP and
   CoreDet show the scale of that change.
