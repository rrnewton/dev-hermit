# Compat-Envelope Scorecard — Phase 1 ("what works today")

Machine-readable cross-backend compatibility measurement, rendered in the owner's
format. Generated by `render-scorecard.rs` from the CSVs in this directory.

- **Denominator**: golden **ptrace**, integer counts of tests passing `--strict`
  verify (strict run + replay verify) — the B4 denominator.
- **Every other backend cell** is `parity%, determinism%` of that ptrace count,
  where **det% ≥ parity% by construction**.
  - `parity%` = fraction of the ptrace-green tests whose output is
    **bitwise-identical** to the ptrace reference.
  - `determinism%` = fraction that run `run1 == run2` (self-deterministic),
    independent of parity.
- **Markers**: `X%?` = parity never measured (UNKNOWN, not a confirmed 0);
  `X%~` = partial parity coverage; `n/a` = backend ran zero cells here
  (binary absent / not enabled) — **not** a confirmed fail.
- **Run**: canonical release run (`run_id canonical-release-ptrace-dbi`),
  hermit `9429005c`, reverie `a4f33d69`, taken on a quiet host. A re-run at
  primary `main` `2f3689bd` was discarded (host under an unrelated ~850 load →
  spurious verify timeouts). See `REPORT.md` → *Measurement conditions*.

## Phase-1 acceptance: is the green-envelope regression enshrined in validate AND CI?

**Partially — validate: yes; CI: authored and pushed, not yet exercised; "across
all backends" only in the privileged lane.**

- **`make validate`** → `make compat-envelope` builds the release hermit binary
  with the in-process DBI backend and runs the green-stays-green regression gate
  (ptrace + DBI). `make compat-envelope-full` adds SaBRe and the reverie
  ptrace-vs-KVM boundary for the privileged runner. ✅ landed on `main`.
- **`.github/workflows/compat-envelope.yml`** has a portable `ubuntu-latest`
  ptrace-denominator job (always-on, PR + push) and an rrnewton-guarded
  privileged self-hosted full-backend job (DBI + SaBRe + KVM/reverie). ✅ landed,
  ⏳ **not yet exercised on GitHub Actions** (needs a triggering push/PR + a
  green run to confirm).
- **All backends in one always-on lane** is bounded by hardware: SaBRe needs its
  loader built, KVM/reverie needs `/dev/kvm`. Those run on the privileged job and
  are honestly `n/a` where absent — never a false red. So the *full* "across all
  backends" enshrinement is real only on the privileged lane, not the portable
  one.

**Bottom line:** validate = enshrined; CI = enshrined in code but pending a green
Actions run; full all-backend coverage = privileged lane only. Phase-2 (a
load-independent full superset where every cell is a confirmed pass/fail) is
still open.
